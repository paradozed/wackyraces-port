# Demos and the attract mode (2026-11-01)

Read from the disassembly. The native run was checked under Xvfb. The demo races were not compared with Wine: the native physics is not the original's to the bit, so a replay of recorded inputs drifts.

## The buffer

`demo1..3.pc` and `.WSR` files are raw dumps of the 0x382f9-byte buffer at `0x6abee0`. They are read by `0x45afb0` (demos) and `0x4b7a30` (`.WSR`). `0x45aff0` restores the buffer:

| Offset | Size | Contents |
|---|---|---|
| `+0x00` | 4 words | App `+0x1a60..+0x1a6c`: game mode, players, player vehicle, second vehicle |
| `+0x10`, `+0x14` | words | Environment (`0x6f41d8`) and course (`0x6f41dc`) |
| `+0x18` | byte | METEO rain flag (`0x6f464c`); the option is restored at the end |
| `+0x49` | — | First controller stream; its length is at `+0x382f3` |
| `+0x382f7` | u16 | Number of recorded updates |

**Playback, `0x45ba30`.** Each update reads the first controller's run counter `0x6abeca`.
- When it is zero, the next three bytes give a run (one byte) and an input word (u16).
- The word less bit 0x800 is the update's input (`0x6e42a0`). The counter is then decremented, so a run byte of 0 lasts 256 updates.
- A second controller and four channels of (run, delta) pairs follow the same scheme. They are not used by the shipped demos.

**Input word** (`0x4399b5..`, stick and buttons):

| Bit | Meaning |
|---|---|
| `0x40` | Accelerate |
| `0x80` | Brake |
| `0x8000` | Left (stick x < −64) |
| `0x2000` | Right (stick x > 64) |
| `0x1000` / `0x4000` | Up / down (menus) |

The three demos' run lengths add up to their update counts:

| Demo | Course | Vehicle | Updates |
|---|---|---|---|
| `demo1.pc` | `cc_t1` | 4 | 2767 |
| `demo2.pc` | `sh_t1` | 1 | 2824 |
| `demo3.pc` | `dt_t3` | 6 | 1760 |

The per-update floats at `+0x111e3` (−2199.5 at the start of `demo1`, then from −22498 to 20644) and the 2-bit states at `+0xeacd` are not decoded.

## Starting a demo

- **DEMO** (setting type 10, `0x48a543`) starts the next of `demo1..3.pc` through the table `0x52beac`, which wraps after 3.
- **Attract mode** (`0x48fac0`) counts menu updates on a node of code 0 or 0x10 without input. Past the `WMenu` action's `m_nMaxIdleTime` it starts the next demo. That value is 300 by default (`0x48f7f0`) and 800 in `menu.WGM` (`0x1a4`). At 30 menu updates a second, that is ~27 s, matching the Wine capture (27..28 s).

## Native

- `game_replay`: `Replay::parse` checks the size, course and vehicle, and reads the controller runs. `ReplayCursor` plays them back.
- `MenuController::idle_update` implements the attract counter.
- `linux_main` handles DEMO and the idle start. The race takes the cursor's word every race update and goes back to the menu, with no post-race menu, when the inputs run out or on Escape/Enter. The exit keys are native: the original's demo exit input is not traced.
- Checks: `native_menu_test` covers the three demos' header and run totals. A native run left idle showed demo1 after ~27 s, playing its 2767 updates, then demo2.
- The player car drifts from the original's line: lap 0 after the demo on `cc_t1`.

## Race recordings (`.WSR`) and REVOIR LA COURSE (2026-11-01)

**Recording.** Every race that is not a replay records its input word each race update, as `0x45b530`'s first controller part does. The word uses the bits above. Runs of up to 255 updates make 3-byte entries, within the `0x2716`-byte stream. When the race starts, the session words, course and rain flag head the buffer, as `0x45b310` writes them.

**Saving and loading.**
- ENREGISTRER LA COURSE (mode 3 of the save screen) writes the raw 0x382f9 bytes as `<name>.WSR` (`0x4b7920`).
- REDIFFUSION, `WMenuNodeLoadSave` `0x119` (mode 2) on the player-count page, lists the `.WSR` files. Its Enter (`0x4962e6`) reads one with `0x4b7a30`, restores it with `0x45aff0` and starts the race.
- REVOIR LA COURSE (post-race row 0) replays the last race. The menu then returns to the post-race menu.

**Not written.** The second controller, the channels, the per-update floats and the 2-bit states stay zero in native files. A native `.WSR` replays only in the port. Original `.WSR` files load, but replay with native physics.

**Checks.** `native_menu_test`: the recording round trip (runs capped at 255, the inputs played back), the post-race save of a 0x382f9-byte `.WSR`, and its listing and playback from the replay page.
