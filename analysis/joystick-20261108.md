# Joysticks (2026-11-08)

## Recovered

- **Devices.** MenuPrefs `+0x18` (player 1, `0x6f4580`) and `+0x1c` (player 2) hold the input
  device: −1 for the keyboard, else a joystick index below the count `0x5419d4`.
  - The options page's JOUEUR item (WMenuSetValueItem type 5, callback `0x48a845`) cycles the
    device: −1, 0 .. count − 1, then back to −1, skipping the other player's.
  - After a change it resets both players' controls (`0x4966f0`), rebinds (`0x406037`) and writes
    the label: string 0x97 (CLAVIER), or string 0xfa followed by the number.
- **Defaults (`0x4966f0`), device not −1.** The control table entries (accelerate, brake, left,
  right, view, look back, gadget, weapon) are 4, 5, 100, 100, 0, 1, 2, 3. The device bits are the
  keyboard's (`0x40000`, `0x80000`, `0x10000`, `0x20000`, `0x100000`, `0x1000000`, `0x800000`,
  `0x200000`).
- **Bindings (`0x40c73e` ff.).** With a joystick, the keyboard keeps fixed keys (arrows, Return,
  '.', right Shift, '/', Escape, space; `0x40c8be`). The joystick device (`+0x1a58`) gets two axis
  objects (`0x405f92` → `0x4391d0`: axis 0 in slot 0, axis 1 in slot 1) and the control table's
  entries + 3 as its buttons (`0x40ca65` ...).
- **Axes (`0x4399b0`).** With `0x6abec8[player]` set, the two axis slots are read as signed bytes:
  - x > 64 gives input bit `0x2000`, x < −64 gives `0x8000` (right, left);
  - y > 64 gives `0x4000`, y < −64 gives `0x1000` (down, up), the bits the arrows give.

## Native

- `wpc::Joystick` (`linux_joystick.cpp`) reads `/dev/input/jsN` (linux/joystick.h) without
  blocking. Its axes are put on the byte scale (value / 256).
- A player's joystick comes from `[input] joystick1/2` or `WPC_JOYSTICK1/2` (−1 keyboard).
- In a race:
  - x beyond ±64 steers, y beyond ±64 accelerates (up) or brakes (down);
  - buttons 4/5 accelerate/brake, 0 camera, 1 rear view, 2 gadget, 3 weapon;
  - the keyboard keeps working beside it.

## Checks and limits

- `native_config_test`:
  - the `[input]` keys, with a bad value and a bad key rejected;
  - the reader on a file of `js_event` records (init events, an axis at −20000 → −78, a button
    press and release);
  - the defaults.
- **Not tested with a real joystick** (none on this machine).
- **Not ported:**
  - rebinding joystick buttons (natively refused on a joystick table);
  - joysticks in the menus and the pause;
  - force feedback.

## The menu's device cycle (later the same day)

### Recovered

- **The trigger.** `0x48cab0` (the page's input) reads the pressed bits:
  - left (`0x8000`) calls the selected item's vtable `+0x50`, right (`0x2000`) its `+0x54`;
  - for WMenuSetValueItem (vtable `0x51373c`) these are `0x48a620` and `0x48a640`, which both call
    the type callback `0x48a660` with 1.
  - For type 5 (`0x48a845`, the JOUEUR rows; `0x195` is the player, 0 or 1), either direction
    steps the device up.
- **The label (`0x48a930`).** String 0x97 (CLAVIER) for −1. Otherwise the number (device + 1,
  `itoa`), `:` (`0x52c43c`), then the DirectInput name at `0x54190c[device] +0x253`. The `0xfa`
  pushed there is the buffer size, not a string.

### Native

- `MenuController::adjust` steps the device for type 5. It goes past the other player's and back
  to −1 beyond the count, then resets both tables (`MenuPrefs::reset_controls`, `0x4966f0`).
- `device_label` gives "number:name" with the joystick names from `/dev/input/js*`. The controls
  page shows a joystick's entries as B1.. (− for 100).
- The race opens the joystick of `MenuPrefs::device(p)`. With a joystick, its buttons come from
  the table, and the keyboard keeps the fixed default keys (`0x40c8be`, `0x40ccb7`).
- `[input] joystick1/2` and `WPC_JOYSTICK1/2` now set that device at start.
- `native_menu_test`:
  - keyboard → joystick 0 → past the other player's joystick → keyboard;
  - the label;
  - both tables;
  - no joystick: no change.

## Menus (provisional)

Outside a race, player 1's joystick drives the menus:
- the stick gives the arrows (the same direction bits as `0x4399b0`);
- the accelerate button accepts: the menus test `0x52aada` = 0x40, which the accelerate control
  feeds;
- the brake button backs out (Escape).

In the pause only the stick and accept are used, so braking cannot leave it. The original's menu
binding list (list 3) for a joystick and its joystick pause key are not traced; nothing here was
tested with a real joystick.
